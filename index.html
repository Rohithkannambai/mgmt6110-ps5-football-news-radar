My agent card | Football News Radar

Finished 20 October 2026, 3:22 AM SGT · written before the first recorded run

  1. The job: Collect new football stories from three outlets into one table for a sports content analyst to monitor and compare coverage.
  2. The trigger: A new item appears in the Sky Sports, BBC Sport or The Guardian football RSS feed.
  3. The tools: RSS by Zapier uses New Items in Multiple Feeds, and Zapier Tables uses Create Record.
  4. It must never: Send or publicly publish an article; its only action is Create Record in my Zapier Table.
  5. Where a person checks: I compare every new table row with its matching Zap History record after each run.

What I expected, what failed and what I fixed

Prediction written at 3:25 AM SGT, before the test

I temporarily replaced the working BBC RSS feed with the ESPN Soccer webpage. Because the ESPN address is a normal webpage rather than an RSS feed, I expected RSS by Zapier to reject it and create no table record.

Observed result and repair

Zapier returned “Unable to pull feeds” with an XML parsing error, and no table record was created. I restored the valid BBC RSS URL, tested the trigger again, confirmed that records were found, and kept the corrected three-feed version published.

Q1 · Where does the agent sit?

The placement follows the map’s two questions and evidence from the runs.

a

My quadrant

AI alone, with checks (bottom left).

b

The two questions

This job has a right answer because every stored field can be compared with the source item and the same Zap History record. In all three real runs, the headline, source feed, summary, article link and published date matched. It is also work that either a person or AI can do alone: a person could monitor three feeds and copy each story manually, but the Zap can perform that repetitive transfer without a person operating each run. The failed ESPN test supports this placement because the error was technical and checkable rather than a matter of taste.

c

The person in the loop

The agent may watch the feeds and create table records on its own. I stay at the verification gate by comparing each new row with its matching Zap History record after a run; if the agent stayed live, I would also make a regular spot check of the table and error log. I check that all five fields match and that a failed trigger has not silently removed a source. The agent must not publish articles or decide which story matters most. If it began ranking stories, judging credibility, writing an editorial angle or deciding what to publish, there would no longer be one right answer, and I would move it to Agents run it, a person judges.

d

My group’s view

I agree with most of our group’s placements because the chosen quadrants match the jobs as they were defined. The customer-feedback agent belongs in Agents run it, a person judges because grouping open comments has no single right answer, while the urgent-email agent belongs in A person decides, AI alongside because urgency depends on the user’s priorities. I would watch the first map question carefully for the daily portfolio summary. If it only copies prices, returns and allocations, the group’s AI alone, with checks placement makes sense because those facts can be reconciled. If it interprets performance or recommends what to buy or sell, I would answer “no single right answer” and move it to A person decides, AI alongside. This shows that a small change in the job can change the person’s role and the correct quadrant.

Three-sentence reflection

The agent fitted the job because collecting and copying feed fields is repetitive, scheduled and objectively checkable. It failed when I supplied a normal ESPN webpage instead of a valid RSS feed, which confirmed that the trigger depends on machine-readable feed input. Next time I would add a monitored fallback source and a simple failure alert while keeping a person responsible for checking the log.
